# Нарушение целостности данных и программного обеспечения (Data and Software Integrity Violation)

### Цель работы

Выявить возможности вмешательства в целостность данных и программного обеспечения веб-приложения. Проэксплуатировать способы подмены, модификации или внедрения вредоносного кода через уязвимости в серверном или клиентском ПО.

## Ход выполнения

### 1) Разведка

В качестве испытуемого был развернут докер с сайтом `owasp-juice.shop`. Переходя сразу к делу, было установлено, что при работе с кошельком пользователя происходит отправка HTTP-запроса на изменение баланса. Ниже перехваченный запрос:

```http
PUT /rest/wallet/balance HTTP/1.1
Host: localhost:3000

...

{
  "balance":10,
  "paymentId":7
}
```

Анализируя данный запрос, можно заметить, что значение **balance** передаётся напрямую с клиента. При этом на стороне интерфейса присутствуют ограничения на ввод, но в самом HTTP-запросе эти ограничения никак не контролируются:

<img width="617" height="323" alt="изображение" src="https://github.com/user-attachments/assets/99ff602d-b042-49f4-bda8-ad89fcd5696f" />

Это указывает на то, что сервер может доверять данным, поступающим от клиента, без дополнительной проверки. В таком случае появляется возможность изменить баланс пользователя, передав произвольные значения в запросе.

### 2) Атака

После выявления уязвимости предпринята следующая махинация: вместо обычного значения было подставлено число, значительно превышающее допустимое:

```http
PUT /rest/wallet/balance HTTP/1.1
Host: localhost:3000

...

{
  "balance":100000000000005,
  "paymentId":7
}
```

### 3) Эксплуатация

После отправки модифицированного запроса сервер успешно обработал его без каких-либо ошибок или отклонений:

<img width="618" height="308" alt="изображение" src="https://github.com/user-attachments/assets/b993def7-8a5f-4b55-bc2c-a116eb445edd" />

Таким образом, была успешно продемонстрирована эксплуатация уязвимости, связанной с нарушением целостности данных. Злоумышленник может изменять баланс на произвольные значения, что напрямую влияет на бизнес-логику приложения.

Данная атака классифицируется как:
- **CWE-20: Improper Input Validation** - недостаточная или некорректная валидация входных данных
- **CWE-345: Insufficient Verification of Data Authenticity** - сервер не проверяет достоверность передаваемых данных
- **CWE-353: Missing Support for Integrity Check** - отсутствие механизмов контроля целостности данных
- **CWE-915: Improperly Controlled Modification of Dynamically-Determined Object Attributes** - возможность изменения критичных параметров объекта через клиентский запрос
