# Небезопасный дизайн (Unsafe Design)

### Цель работы

Выявить недостатки проектирования веб-приложения, которые создают векторы атак, не связанные напрямую с ошибками реализации или конфигурации. Проанализировать логику работы приложения на предмет нарушений принципов безопасного проектирования, таких как недостаточная проверка действий пользователя, отсутствие ограничений на выполнение критических операций или несоответствие предполагаемой модели угроз.

### 2) Атака

Анализ перехваченных запросов показал, что после отправки формы сначала загружается страница с параметрами в URL (GET /), а затем отправляется запрос к API для отправки email. Ключевой запрос для атаки — `GET /api/email/sendSupportEmail`, так как он выполняет целевое действие (отправку письма) и использует cookie сессии для авторизации. Можно отметить, что запрос не содержит никаких защитных механизмов: нет анти-CSRF токенов, нет проверки Origin или Referer заголовков, а все параметры передаются прямо в URL.

Для демонстрации уязвимости была создана простая HTML-страница, которая автоматически отправляет такой же запрос от имени жертвы:

```
<html>
  <body>
    <img src="https://brokencrystals.com/api/email/sendSupportEmail?name=Attacker&to=hacker@mail.ru&subject=Hacked&content=Your%20account%20is%20compromised">
  </body>
</html>
```

При загрузке страницы браузер автоматически отправил GET-запрос на указанный URL, используя существующие cookie сессии. Ниже перехваченный запрос:

## Выводы о защищенности

В результате анализа выявлена уязвимость класса CSRF, обусловленная недостатками проектирования: отсутствие анти-CSRF токенов и проверки источника запроса позволяет выполнять действия от имени авторизованного
пользователя без его ведома. Это нарушает принцип безопасного взаимодействия с пользовательскими сессиями и может привести к несанкционированному изменению данных или выполнению критических операций. Данная атака
классифицируется как **CWE-352: Cross-Site Request Forgery** (CSRF).
